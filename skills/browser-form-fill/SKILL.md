# 浏览器表单填写

把「用户给的一批信息」填进网页表单，**结构化定位，不靠截图猜**。

## 权限边界（最高优先级）

这个 skill 会**真实地**在用户浏览器里写东西。规则：

- 🔴 **永远跳过**：`type=password`、验证码（captcha/otp/2fa）、支付字段（card/cvv/cvc）、签名/同意勾选的最终提交按钮。
- 🟡 **必须先列清单再动手**：把「字段 → 填什么」列成表，等用户说「确认」才开始填。
- 🟢 **默认不提交**：填完就停，最后一步「提交」由用户自己点。
- 🔴 **填错了不回滚**：浏览器没有 undo，所以列清单这一步不能省。

## 工作流

### 1. 拿到要填的数据
用户会给你一份信息（聊天里贴的、文件里的、或口述）。整理成字典：

```
字段名（中文/英文） → 值
```

如果用户没给某字段，**留空并问**，不要瞎编。

### 2. 打开表单，读 accessibility tree
用浏览器后端（Playwright MCP / bsk）打开页面，调用 `browser_snapshot`（或等价的 accessibility tree 接口）。**不要截图让模型猜**——用结构化文本里的 `ref` / `name` / `role` 定位。

### 3. 字段匹配
把用户给的字段和页面上的 label 对齐：

| 用户给的 | 页面上的 | 匹配方式 |
|---|---|---|
| 姓名 | "Full name" / "姓名" | 同义 + 大小写不敏感 |
| 邮箱 | "Email" / "电子邮箱" | 正则 `^[\w.+-]+@[\w-]+\.[\w.]+$` |
| 电话 | "Phone" / "手机" | 数字+国家码 |
| 日期 | "Date" / "日期" | ISO `YYYY-MM-DD` |

**匹配不上的字段**：列出来问用户，不要硬塞到相近字段。

### 4. 列清单（必须）
填之前输出：

```
将填写以下字段（共 N 项）：
- 姓名 → 张三
- 邮箱 → zhangsan@example.com
- 电话 → 138****0000

已跳过：密码、验证码、支付字段（共 3 项）
不会自动点「提交」。

确认请回复「确认填写」。
```

### 5. 逐项填写
用户确认后，按 accessibility tree 的 `ref` 逐个 `fill` / `click`：

- 文本框：`fill(ref, value)`
- 下拉：先 `click` 展开，再 `select` 选项
- 单选/复选：`click(ref)`
- 日期：按页面要求的格式填

每填 3-5 项，回一次 snapshot 确认没填错位置。

### 6. 收尾
- 填完后再 snapshot 一次，把实际填入的值列给用户核对。
- 提醒用户自己检查、自己点提交。

## 脚本辅助：字段分类器
`scripts/classify_fields.py` 可以帮你把用户给的原始字段名映射到标准类别，并标注哪些是敏感字段：

```bash
python scripts/classify_fields.py "姓名,邮箱,密码,身份证,公司"
# output:
# name      -> safe
# email     -> safe
# password  -> SKIP (敏感)
# id_card   -> SKIP (敏感)
# company   -> safe
```

## 何时不该用
- 表单需要验证码——告诉用户这步得自己来。
- 表单是支付/汇款——直接拒绝，让用户自己操作。
- 用户要你「自动提交」——拒绝，坚持最后一步留给人。
